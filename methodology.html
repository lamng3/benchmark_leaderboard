Evaluation methodology

Measure the model.
Measure the system.

A strong LLM does not guarantee a strong ontology integration system. We evaluate model capability and workflow orchestration as separate, traceable dimensions.

Unit of comparisonOne evaluated run
Controlled byTask + pair + protocol
Compared acrossModel + workflow

The core idea

Two axes explain every result.

Model capability captures what the underlying LLM can recognize, extract, and reason about. Workflow lift captures what orchestration adds through ordering, iteration, tool use, and feedback.

Ranking only by model hides workflow effects. Ranking only by workflow hides model effects. The leaderboard records both so a run can be compared fairly along either axis.

Scoring

Metrics answer different questions.

Precision

How many predicted relations or alignments are correct?

Recall

How much of the gold alignment did the system recover?

F1

What is the harmonic balance between precision and recall?

MCC

How balanced is classification quality across all outcomes?

Pass@1

How often does the first generated answer pass end-to-end?

Chain accuracy

Can the system verify multi-step relational reasoning?

Fair comparison rules

When does a ranking count?

  1. 01
    Same task

    Do not rank different evaluation objectives against one another.

  2. 02
    Same ontology pair

    Pair difficulty and overlap must remain visible.

  3. 03
    Same protocol

    Sampling, top-k, iteration count, and gold sets must match.

  4. 04
    Named model

    Record model version—not only a provider or family name.

  5. 05
    Traceable workflow

    Report ordering, feedback, and component configuration.
